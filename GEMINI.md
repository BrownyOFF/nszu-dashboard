Документація проєкту "НСЗУ: Аналітика та Аудит"
📌 Огляд проєкту
Проєкт складається з двох взаємопов'язаних веб-додатків, призначених для обробки, конвертації та візуального аналізу медичних звітів Національної служби здоров'я України (НСЗУ).
Усі обчислення та обробка даних відбуваються виключно на стороні клієнта (Client-side), що гарантує конфіденційність медичних даних.

Автор: Тимур Галас (GitHub: BrownyOFF)

🛠 Технологічний стек
Основа: Vanilla HTML5, CSS3, JavaScript (ES6+).

Дизайн: Власна CSS-система з використанням CSS Variables (кольори, відступи, тіні). Шрифт: Plus Jakarta Sans.

Бібліотеки (через CDN):

SheetJS (xlsx.js) — для парсингу XLSX файлів у браузері (converter.html).

Chart.js — для рендерингу графіків та діаграм (index.html).

Збереження даних: localStorage (використовується для збереження налаштувань цін на медичні пакети).

📂 Структура файлів
1. converter.html (Розумний Конвертер)
Призначення: Конвертація об'ємних .xlsx звітів НСЗУ у формат .json для подальшого швидкого аналізу.

UI: Drag-and-drop зона для завантаження файлу.

Логіка: * Зчитує файл як ArrayBuffer.

Проходить по всіх листах (sheets) книги Excel.

Конвертує кожен лист у масив об'єктів JSON за допомогою XLSX.utils.sheet_to_json.

Генерує .json файл для завантаження на комп'ютер користувача.

2. index.html (Аналітика та Аудит)
Призначення: SPA (Single Page Application) дашборд для завантаження згенерованого JSON та його глибокого аналізу.

UI: Бічна панель навігації, система вкладок (Tabs), адаптивна сітка (Grid/Flexbox) для карток з графіками.

Модулі (Вкладки):

🏠 Загальний огляд: Статистика успішності, тренди (Line chart), співвідношення помилок (Doughnut chart).

🚨 Аудит помилок: Аналіз причин відхилення записів. Важливо: включає специфічний парсер для вилучення вкладеного JSON з текстових рядків у колонці "деталі".

💰 Фінансовий вплив: Розрахунок зароблених та втрачених коштів на основі системи тарифів.

👨‍⚕️ Аналіз по лікарях: Рейтинги лікарів за доходом, кількістю помилок та навантаженням.

👶 Портрет пацієнта: Віковий розподіл (фокус на дітей 0-17 років).

📄 Реєстр записів: Таблиця сирих даних з пагінацією (по 15 записів).

⚙️ Налаштування: Керування тарифами (цінами) для кожного пакету НСЗУ.

🗄 Модель даних та Парсинг (Data Mapping)
Система автоматично шукає рядок із заголовками (header row) та зіставляє їх із внутрішніми ключами об'єкта MAP. Це робить додаток стійким до зміни порядку колонок у звітах НСЗУ.

Ключі мапінгу (MAP object):

id: "id емз"

date: "внесено до есоз" або "дата"

doctor: "медичний працівник" або "виконавець" (без слова "посада")

pkg: "пакет послуг" або "пакет"

isReport: "включення... звіту" (Очікуване значення для успіху: "Так")

error: "коментар... помилок"

patientId: "унікальний код пацієнта"

age: "вік пацієнта"

details: "деталі... нсзу" (Часто містить екранований JSON з детальними причинами відмови).

diag: "основний діагноз"

diagSec: "супутні діагнози" (зазвичай перелік через кому)

Опис помилок (Error Descriptions): Якщо у файлі є лист "Опис помилок", система створює довідник кодів для відображення детальних розшифровок у реєстрі при наведенні миші.

Організація (Org Info): Система намагається автоматично знайти назву закладу та код ЄДРПОУ у перших 15 рядках файлу.

💰 Бізнес-логіка (Система тарифів)
У додатку реалізовано динамічну систему оцінки вартості послуг:

За замовчуванням використовуються базові тарифи (DEFAULT_RATES):

Пакет "9" (напр. стоматологія): 1200 ₴

Пакет "4": 800 ₴

Інші пакети: 450 ₴

Користувач може змінити тарифи у вкладці "Налаштування".

Нові тарифи зберігаються у localStorage під ключем nszu_prices.

Функція getPrice(pkgName) повертає актуальну вартість для розрахунку вкладки "Фінансовий вплив" та рейтингу лікарів.

🚦 Правила для AI при внесенні змін
Не порушувати Client-side підхід: Не пропонувати бекенд-рішення (Node.js, Python тощо). Проєкт має залишатися статичним HTML/JS для запуску прямо в браузері.

Стилістика коду: Зберігати використання існуючих CSS-змінних (напр., var(--primary), var(--danger)).

Бібліотеки: Для будь-яких нових візуалізацій використовувати виключно Chart.js.

Продуктивність: При обробці великих масивів даних (filteredData, allData) використовувати оптимізовані методи масивів (filter, reduce, map), оскільки звіти НСЗУ можуть містити десятки тисяч рядків.

Безпека (DOM): При рендерингу даних з файлу в DOM (наприклад, у таблицю сирих даних), зважати на можливі непередбачувані символи у звітах.
